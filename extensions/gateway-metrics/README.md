# Gateway request metrics

This Rust dynamic access logger targets the Envoy version pinned in docker/Dockerfile.gateway. It records one counter update and one duration observation at DownstreamEnd. It has no Istio or Rust crate dependencies. The gateway image contains /usr/local/lib/libagentio_gateway_metrics.so; loading it remains an explicit listener configuration change. This does not replace the control plane's existing istio.stats configuration.

The module emits istio_requests_total with response_code (100–599, or 0 when no valid response status exists), and an aggregate istio_request_duration_milliseconds histogram without business labels. Duration uses StreamInfo requestComplete, converted to integer milliseconds, including interrupted requests. It uses Envoy's default histogram boundaries unless overridden through the agent's existing histogram settings. Counters for all supported codes are registered during configuration initialization, as required by the host ABI; zero-valued series can therefore appear before traffic. Metrics are updated without module-level locks or per-request allocations.

Configure metrics_namespace as agentio_gateway and use the response_code tag extraction in pkg/gatewayagent/testdata/dynamic-metrics.json. Envoy Admin exposes envoy_agentio_gateway_istio_* names. The gateway-agent metrics handler converts just these metric names to istio_*, including TYPE and HELP declarations. Both the agent status port and Envoy's forwarded Prometheus port use this handler. Prometheus adds namespace and pod from discovery; the module does not emit them.

Build the shared object using cargo build --release --locked --offline in this directory, or docker build -f docker/Dockerfile.gateway --target metrics-artifact --output type=local,dest=out/gateway-metrics . from the repository root. The Docker build compiles for the target platform. The final gateway image includes the module automatically.

The standalone Envoy configuration pkg/gatewayagent/testdata/dynamic-metrics.json listens on 19800 with Admin on 19900 and provides status-code routes such as /200, /403 and /418. Mount the module at its configured path and start Envoy with that configuration. This standalone configuration exposes raw Admin metric names; the integration test additionally runs the agent's real metric handler and bootstrap-generated Prometheus listener to validate the existing scrape contract.

Run bin/test_gateway_runtime.sh to build the module and test it with the pinned community Envoy. Passing a gateway image as its argument tests the module packaged in that image. The existing agentio-ut gateway-runtime job runs this test; no separate workflow is added. It checks final status codes, aborted requests with code 0, histogram counts and bucket boundaries, and both metrics endpoints. Loading the module in an incompatible Envoy is unsupported; upgrade the pin and ABI subset together and rerun this test. As a native module, a module crash affects the Envoy process.
