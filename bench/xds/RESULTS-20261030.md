# Gateway xDS correctness and performance fixes

Initial measurements below used upstream master `c1629ffd450854c2846cbc961ad39418cccc47f1`.
The branch was subsequently rebased to `3162d74c` (see Git for the full SHA). Upstream now generates independent descriptor action groups, so the earlier first-CEL patch and its obsolete regression test were dropped. The timings below are historical and are not the comparison against this newer base.

Branch: `codex/xds-master-correctness`. Measurements: Apple M4, darwin/arm64, Go 1.26.8.

## Changes

- Track outstanding deliveries of generic gateway resources separately from unpublished demand resources. After a NACK, the next configuration update or explicit subscription reconciles uncertain updates and removals. Late acknowledgements resolve only their own outstanding deliveries. Pure NACKs do not immediately retry invalid configuration.
- Honor explicit generic subscriptions even when the name and version are already recorded as sent; preserve aliases, internal keys, and gateway visibility.
- Generate explicit release-default HTTP path handling for native and legacy gateways: normalize paths, retain escaped slashes, and leave slash merging disabled. Use the rebased upstream descriptor action groups for CONNECT rate limiting.
- Reuse the existing gateway ownership index for selection and reject unrelated ownership identities before considering withdrawals of same-name resources.
- Share mailbox merges only between subscribers with the same immutable pending notice. Distinct intermediate identities and full-refresh scopes remain distinct. The latest upstream candidate-reuse optimization is retained.
- Gateways with a primary ext_proc override depend only on global additional processors. Explicitly disabled gateways do not depend on either global provider input. Removing an override restores inheritance.

## Validation

Before rebasing, the new recovery, explicit-subscription, path-normalization, duplicate-CEL and compiler-dependency checks failed on the original unmodified base and passed with the fixes. The duplicate-CEL check is obsolete and was removed after rebasing. The base reproduces missing resource `b` after NACK recovery, suppressed explicit subscriptions, differing path defaults, last-CEL selection, and three gateway recompilations for a primary-provider change instead of one.

## Microbenchmarks

Median of three sequential runs per revision, `-benchtime=300ms`; base and patched code use the same benchmark fixtures.

| Scenario | Base | Patched |
| --- | ---: | ---: |
| Cold selection of one gateway among 1,000 | 4.081 ms/op | 4.226 µs/op |
| Another gateway changes a shared wire name, 1,000 gateways | 213.791 µs/op | 138.1 ns/op |
| 1,000 gateways and 1,000 subscribers with queued updates | 32.484 ms/op | 7.663 ms/op |

Cold-selection allocation bytes fell from about 6.74 MB/op to 15.1 KB/op; the unrelated update fell from about 486 KB/op to zero allocations. Backlog allocation bytes remain about 12.15 MB/op: the additional benefit over current master is primarily avoiding repeated merge computation.

```sh
go test ./pkg/xds -run '^$' \
  -bench '^BenchmarkGateway(ColdSelection|UnrelatedIncremental)$/^gateways=1000$' \
  -benchtime=300ms -count=3
go test ./pkg/xds/store -run '^$' \
  -bench '^BenchmarkStoreGatewayBacklog$/^gateways=1000$/^subscribers=1000$' \
  -benchtime=300ms -count=3
```

These measure selection and publication paths, not end-to-end controller throughput. The compiler dependency check counts actual transforms: a global primary change rebuilds only the inheriting gateway; an additional-provider change rebuilds the inheriting and overriding gateways, excluding the disabled gateway.

## Limits

The patch was not deployed to kind and the existing 24-hour baseline run was not modified. Real Envoy NACK recovery and patched path behavior have not been exercised in the cluster. Full repository and runtime suites were not run.

Path normalization intentionally changes the previous master default to match release; custom legacy MeshConfig normalization modes are not introduced here. Dual legacy/native graph generation remains. Connection-pool cardinality was outside this xDS investigation; the subsequent filter-state changes and their runtime validation are documented in [FILTER-STATE-20261031.md](../connect/FILTER-STATE-20261031.md). Mixed-version SNI/EPE compatibility and send-error classification remain outside this work. Independent RDS, last-known-good configuration behavior and legacy EnvoyFilter context handling remain unchanged by this patch. Protocol inspection follows the newer upstream behavior, including closing on detection timeout.

## Local benchmark comparison after rebase

The new base is `3162d74c996845086f2421348af180a7520f5199`; the candidate is that base plus the uncommitted changes on this branch. The older microbenchmark table above must not be treated as results against this base.

The completed local screen covers 216 subcases across eight packages, with 39 subcases repeated in six alternating rounds (including two extra small-inventory ACK cases, for 218 distinct scenarios). The full local comparison and raw samples are saved outside the repository at `/tmp/agentio-xds-fullbench-3162d74c/`. See `REPORT.md` there for scope, timings, repetition counts and limitations. Before the follow-up optimization, the focused six-round alternating comparison found a normal gateway delivery/ACK CPU cost (8–17% in the significant cases), plus 14–17% more allocated bytes in the scheduler benchmark from the larger update structure. These are measurements of the earlier repair, not the current candidate.

The follow-up on `my-ecs` compares pure master, the earlier repair and the optimized repair over 22 subcases with six samples per revision. The optimized candidate tracks a single outstanding response without indexing every resource, skips fully superseded deliveries, and keeps mailbox IDs in subscribers instead of Update. Normal ACK timings and scheduler allocation bytes returned close to baseline. Remaining significant CPU differences include +2.12% for 64 full updates before ACK, +0.61% for 64 distinct updates before ACK, and +4.89% for publication to 10,000 subscribers without backlog. The 1,000-gateway/1,000-subscriber backlog remains about 71% faster than master. Full methods, raw evidence and limits: `/tmp/agentio-xds-perf-investigation-20261030/REPORT.md`.

The follow-up passed local xDS/Store race tests, Linux xDS/Store tests and incremental lint. It was not deployed to kind; real-network P99 and peak heap under prolonged ACK delay were not measured.
